## 형태 스케일 — 반경·상승·숫자

**새 값을 만들지 않는다.** 상자마다 다른 반경·그림자를 쓰면 판정 문서가 위젯 모음으로 읽힌다.
이 문서의 격은 장식이 아니라 **한 벌로 맞은 형태**에서 나온다.

| 축 | 값 | 쓰는 곳 |
|---|---|---|
| 반경 | `--r-lg` 12px | 컨테이너 — 표 · 카드 · `.surface` · `.part` · `.fig` · `.layer` |
| | `--r-md` 8px | 안쪽 요소 — `.node` · `.fbox` · `.edge` · `.chips` · 막대 트랙 · 행렬 칸 |
| | `--r-pill` 9999px | `.tag` 배지뿐 |
| 상승 | `--shadow` | **`.part` 판에만** 쓴다 |
| | `--shadow-sm` | **`none` 이다.** 위계는 그림자가 아니라 머리카락 선(`--rule`)과 여백으로 만든다 |

- **표 머리행은 채우지 않는다.** 회색 채움 대신 `1.5px` 잉크 밑선 하나로 본문과 가른다 —
  인쇄물의 표가 쓰는 방식이고 잉크도 덜 먹는다
- **숫자는 전부 고정폭이다**(`font-variant-numeric:tabular-nums`). 열에 수가 쌓이는 문서에서
  자릿수가 어긋나 보이는 것이 격을 가장 빨리 떨어뜨린다
- **절은 머리카락 윗선으로 열린다.** 단 `.part` 판 다음 절은 선을 얹지 않는다(판이 이미
  경계다). 인쇄에서는 절 윗선을 끄고 판의 `3px` 윗선 하나만 남긴다 — 선이 세 겹으로 쌓이면
  지저분해진다
- **하드코딩 색을 쓰지 않는다.** 노랑이 필요하면 `--st-gap-*`(갭 계열)을 쓴다. 팔레트가 문서
  안에서 흔들리면 격이 떨어진다
- **원문 인용(`.q`)은 링크색이 아니다.** 같은 파랑의 더 깊은 색조(`#1B3F9E`)를 쓴다 — 밝은
  파랑이면 표 안에서 인용이 본문보다 먼저 읽혀 행의 뜻을 가린다

## 왜 mermaid 를 쓰지 않는가

CDN 스크립트를 붙이면 파일이 혼자 이동할 때(메일 첨부·사내 공유) **스크립트 차단 환경에서
그림이 통째로 사라진다.** 자기완결 문서에서 그림이 사라지면 논증의 절반이 없어진다.
그래서 도해를 HTML/CSS 로 직접 그린다. 아래 클래스로 대부분 그려진다.

## 도해 클래스

| 클래스 | 무엇을 그리는가 | 쓰는 곳 |
|---|---|---|
| `.stack` `.layer` `.node` | **Layer 스택.** `flex-direction:column-reverse` 다 — **마크업은 Layer 1 부터 위 Layer 순서로 쓰고**(`.layer.L1` → `.L2` → `.L3`) 화면에서는 뒤집혀 아래가 Layer 1 로 보인다 | 파트 2 #01 |
| `.erow` `.edge` | Layer 사이 화살표 행. `.edge.hot` 은 충돌이 몰린 선 | Layer 스택 안 |
| `.pair` `.bidi` | Layer 1 안의 양방향 관계(서로를 기다리는 두 Workstream) | Layer 스택 Layer 1 |
| `.flow` `.fcol` `.fbox` `.fsep` `.fcap` | **가로 흐름.** 구간 배분·순환 도해·순서 도해 | 파트 2 #02(순환)·파트 4·파트 5 #01 |
| `.fbox.gate` `.fbox.cap` | 게이트(초록)·상한(주황) 강조 | 흐름 안 |
| `.bars` `.bar` | **막대.** Workstream 별 관여 수, 표지 실측 | 파트 1, 표지 |
| `.mx` | **인접 행렬.** 쌍별 Contract 수 | 파트 1 #02 |
| `.surface` `.sfh` `.sfv` | **Contract 카드.** 상태별 왼쪽 테두리 색 | 파트 3 |
| `.cards` `.c2` `.c4` `.card` | 카드 격자. `.card.base`(파랑) `.card.risk`(주황) | 전체 |
| `.xr` | **이 문서 안을 가리키는 상호참조.** 연파랑 글자 + 잔은 점선 밑줄 | 본문 전체 |
| `.chips` | **Contract 색인.** ID 전량을 상태 색 칩으로. `id="cidx"` 를 함께 준다 | 파트 3 #01 끝 |
| `.sub` | 목차의 **서브 항목.** 절 제목만으로 도달하지 못하는 이름에만 | 목차 |
| `.tq` | 목차 파트 라벨의 **한국어 질문.** 본문 `h2` 와 같은 문구 | 목차 `.tgrp` 안 |
| `.part` `.pn` `.pr` `.pmeta` | **파트 구분자.** 어두운 판. 인쇄에서 흰 바탕 + 굵은 윗선으로 바뀐다 | 파트 시작 |
| `.brief` `.bt` `.bn` | **프로그램 설명 상자.** 판정 제목 앞에 온다. `.bt` 는 라벨, `.bn` 은 마지막 단락(*"이 문서는 제품 설명이 아니다"*) | 표지 — `h1` **앞** |
| `.pidx` | 표지의 파트 안내 카드 | 표지 |
| `.tag` | 판정 배지 — `.yes` `.no` `.warn` `.st-con` `.st-dup` `.st-gap` `.st-ok` | 표 안 |
| `.q` | 원문 인용. **기울임을 쓰지 않고** 색과 굵기로 표시한다 | 전체 |

`.tw` 는 표 래퍼다. 표는 항상 `<div class="tw"><table>…` 로 감싼다 — 좁은 화면에서 가로
스크롤이 필요하기 때문이다.

## 색 축 세 개

색을 섞으면 독자가 규칙을 못 찾는다. 축을 셋으로 나눠 두었다.

1. **주체** — `--human-*`(사람) `--agent-*`(에이전트) `--engine-*`(엔진). 원래 덱 규약의
   의미 삼색이다
2. **판정** — `--yes-*` / `--no-*`. 가능·불가에만 쓴다
3. **상태 4분류** — `--st-con`(충돌 빨강) `--st-dup`(중복 주황) `--st-gap`(갭 노랑)
   `--st-ok`(정리됨 초록). hue 를 네 개로 벌려 한눈에 갈리게 했다

읽는 문서에서는 `--agent-*` 를 **구조 강조**(Layer 1 · 두꺼운 경계·큰 수치)에도 쓴다. 덱과 달리
"파랑=에이전트" 를 가르치는 자리가 없기 때문이다. 의도적 이탈이므로 CSS 주석에 이유를
남겨 둔다.

## 인쇄 규칙

고객은 PDF 로 회람한다. 화면에서 멀쩡한 것이 인쇄에서 깨지는 자리가 넷이다.

**① 파트는 새 페이지에서 시작한다.** `.part{page-break-before:always}`. 첫 파트만 예외다.
어두운 판은 잉크만 먹으므로 인쇄에서 흰 바탕 + 굵은 윗선으로 바뀐다.

**② `.surface` 에는 분할 금지를 걸지 않는다.** 카드 스무 장에 `page-break-inside:avoid` 를
걸면 카드 하나가 페이지를 통째로 차지해 **인쇄 분량이 두 배**가 된다. 안쪽 `table` 이 이미
분할을 막으므로 카드는 표와 "확정 대상" 사이에서만 갈린다.

**③ 행이 많고 두꺼운 표는 `.tw.split` 을 붙인다.** 기본값 `table{page-break-inside:avoid}`
때문에 그런 표는 통째로 다음 페이지로 밀리고 **앞 페이지가 절반 이상 빈다.** `.tw.split` 은
행 사이에서 갈리게 하고 행 자체는 `tr{page-break-inside:avoid}` 로 지킨다. 다섯 행 이상이고
각 행이 세 줄 이상이면 붙인다고 보면 된다.

**④ 가로 흐름 도해는 인쇄에서 활자를 줄인다.** A4 본문 폭이 화면보다 좁아 마지막 칸이
잘려 나간다. `@media print` 에서 `.fcol{min-width:0}` `.fbox{padding:9px 6px}` 등으로
줄여 두었다.

인쇄 공백은 눈으로 못 찾는다. `scripts/to_pdf.py` 가 **페이지별 글자 수를 세어 420자 미만**
을 알려 준다. 파트 구분자와 절 끝 페이지만 남으면 정상이다.

## 도달점 — 참조하는 이름에는 갈 자리가 있어야 한다

**이 문서는 첨부로 혼자 이동하고 물어볼 사람이 없다.** 그래서 무엇을 이름으로 부르면 그 이름으로
찾아갈 수단이 함께 있어야 한다. 실사용 판에서 네 자리가 이 규칙을 어겼고 **전 검사를 통과했다** —
논리·수치가 아니라 **탐색의 결함**이라 기계가 보지 못한다.

| 참조하는 것 | 도달 수단 | 어긋났던 자리 |
|---|---|---|
| 절·파트(「파트 4 #02」) | `.xr` 링크 + 목차의 파트 번호 | 목차에 파트 번호가 없어 「파트 6」을 못 찾았다 |
| **Contract ID** | **본문의 `.m` 배지를 앵커로**(`<a class="m" href="#C11">C11</a>`) + 색인 · 전량 표 행 `id` | 색인만 있으면 두 단계고, 눌리지 않는 회색 배지는 「누를 수 있어 보이는데 안 눌리는」 오독을 만든다 |
| 축(「②축」) | 세 축 지도가 그 축의 **전량이 있는 절**을 가리킨다 | 지도가 부분집합 절(§4)을 가리켰다 |
| 단위(Contract·Layer·Workstream) | **파트 1 #01 머리의 정의표** | 표지가 「Contract 40개」를 정의 없이 먼저 말했다 |

- **본문의 ID 참조 `.m` 배지는 앵커로 감싼다.** 색인만 두면 두 단계다(색인으로 스크롤 →
  그 칩을 다시 누른다). 그리고 `.m` 은 배경·테두리가 있어 **누를 수 있는 것으로 보인다** —
  안 눌리면 그 자체가 오독이다. 스타일은 그대로 두고 `hover` 때만 파랑으로 힌트를 준다 —
  색인 칩(`.chips a`)과 시각적으로 구별되어야 한다
- **골격 주석에 태그를 적지 않는다** — `check_html.py` 의 태그 균형·깨진 앵커 검사는 HTML
  주석을 **제외하지 않는다.** 앵커 예시 한 줄에 어긋남 9건이 났다(실측). 클래스명과 속성
  이름만 백틱으로 적는다

## 상호참조 — **`§` 는 원문 전용이고 이 문서는 `#` 을 쓴다**

**기호로 대상을 가른다.** 이것이 첫 신호이고 `.xr` 밑줄이 둘째 신호다.

| 가리키는 것 | 표기 | 감싸는가 |
|---|---|---|
| **이 문서의 절** | **`파트 4 #02`** — `#` + **두 자리** 번호 | `.xr` 로 감싼다 |
| 고객 원문의 절 | `§4.1` · `§5` — `§` 를 쓴다 | 감싸지 않는다(원문 표기 그대로) |

```html
개수 카드와 사전 준비 표는 <a class="xr" href="#s42">파트 4 #02</a> 에 있다.
REQ <span class="q">§3.1.4</span> 는 표시 시간에 값을 주지 않는다.
```

- **`#` 을 고른 이유는 앵커와 같은 기호라는 것이다** — `파트 4 #02` 를 누르면 `#s42` 로 간다.
  표기와 도달 수단이 같은 글자를 쓰고, **ASCII 라 폰트 이탈 위험이 0** 이다(폰트 축은 네 판
  연속 뚫렸다)
- **번호는 두 자리다** — 목차·본문 절 번호(`.sn`)가 `01`·`02` 이므로 참조도 `#01`·`#02` 로
  맞춘다. 실사용에서 **절을 「1」·「01」·「§1」 셋으로 부르던** 자리를 이것으로 닫는다
- **`#02` 만 쓰지 않는다** — 파트 번호를 함께 적는다(같은 파트 안이라도 「이 파트 #02」)
- 대상 id 는 절이 `#sNM`(파트 N 의 M번째 절), 파트가 `#pN` 이다
- 범위 표기(「이 파트 #01~#03」)는 **첫 절에 건다**

**근거는 실사용 판이다.** 산출물이 *"판정은 이 문서의 ②축"* 이라고 적어 두고도 독자가 그 축을
찾지 못했다. 원문 참조가 `§4.1` 69회 · `§5` 56회인데 이 문서 참조가 **같은 `§`** 로 34회라 두
대상이 섞였고, **본문 상호참조는 링크가 아니어서**(그 판의 링크는 목차 18개뿐) 클릭해 확인할
수도 없었다. `.xr` 이 밑줄을 주고 **`#` 이 기호를 가른다** — 두 신호가 겹친다.

**스크립트가 `§` 를 원문 참조로 파싱한다** — `check_numbers.py` 의 세 자리(숫자 앞 `§` 면 수치로
세지 않음 · `cites` 앞머리 분리 · `startswith("§")`)와 `term_sweep.py` 의 출력 형식(`문서 §절`)
이다. **그래서 원문 쪽 `§` 를 바꾸지 않는다** — 이 문서 쪽만 `#` 으로 옮기면 그 다섯 자리가
오히려 깨끗해진다(지금까지 이 문서 참조가 그 필터에 섞여 들어갔다).

`check_html.py:145` 가 깨진 앵커를 잡으므로 감싸면 검증까지 붙는다.

## 목차와 스크롤 스파이

좌측 고정 목차 + 스크롤 스파이 구조다. 절을 추가하면 목차에도 한 줄 추가한다 —
`check_html.py` 가 깨진 앵커를 잡아 주지만, **목차에 없는 절은 잡아 주지 않는다.**

- `.tgrp` = 파트 라벨. 클릭 이동은 되고 **활성 표시 대상에서는 빠진다**. 파트와 절이 동시에
  활성으로 보이면 지금 어디인지가 오히려 흐려진다
- **파트 번호를 목차와 본문 양쪽에 준다** — 목차는
  `<span class="n">파트 4.</span>Where it closes`, 본문 파트 구분자는
  `<div class="pn">파트 4. Where it closes</div>` 다. **낱말을 「파트」로 적는다** — 본문이
  「파트 4 #02」로 참조하므로 표시도 같은 낱말이어야 대응이 보인다(영문 `Part 4` 는 참조와
  낱말이 갈린다). 두 자리의 형식을 같게 유지한다. 실사용 판에서
  **절에는 번호가 있고 파트에만 없어서** 독자가 「파트 6」을 찾지 못했다 — 목차에 `SCOPE`·
  `ORDER`·`START` 만 보이면 「파트 4 #02」를 조립하려고 파트를 세어야 한다. 본문이 파트를
  번호로 참조하므로 **보여 주는 쪽도 번호를 가져야 한다**
- `.brand` = 맨 위로 가는 링크. `<a>` 로 만들면 `#toc a` 의 항목 스타일이 얹혀 왼쪽으로
  밀리므로 `padding:0 0 14px` `margin:0 0 16px` `border-left:0` `border-radius:0` 을 명시해
  덮는다
- 스파이 쿼리는 **`#toc a:not(.tgrp):not(.brand)`** 다. `.brand` 를 빼지 않으면 표지가
  섹션으로 잡혀 브랜드 줄에 활성 표시가 붙는다

**인쇄에서 목차는 숨는다**(`#toc{display:none}`). 그래서 PDF 에는 목차도 페이지 번호도
없다 — Chrome 이 CLI 인쇄에서 북마크를 만들어 주지 않는다. 고객에게 "파트 N #0M 을 보세요"
라고 안내할 거면 **HTML 을 먼저 열도록 권하는 한 줄**을 메일에 넣는 편이 낫다.

## 폰트에 없는 글자

**이탈은 「글자」가 아니라 「글자 × 그 자리의 폰트 체인」에서 갈린다.** 두 체인이 다르다 —
`--sans` 는 `Pretendard → system-ui` 이고 `--mono` 는 `Geist Mono → SF Mono → Pretendard` 다.
그래서 **Geist Mono 에는 있고 Pretendard 에 없는 글자는 mono 자리에서 안전하고 sans 자리에서
이탈한다.** `pdffonts` 에 `AppleSDGothicNeo`·`.SFNS`·`Menlo` 가 뜨면 그 신호다.

- **없다**: `⇄`(U+21C4) · `⇕`(U+21D5) · `▸`(U+25B8) · 한자
- **있다(검증됨)**: `⇔ ⇐ ⇒ ↔ ↕ → ← ↑ ↓ · ＊ •`
- **자리에 따라 갈린다**: `├ │ └` — **박스 드로잉은 Pretendard 에 없고 Geist Mono 에 있다.**
  페이지별 `pdffonts` 로 확인했다: 셋 다 `--sans` 에서 `.SFNS-Regular`·`AppleSDGothicNeo-Regular`
  로 **이탈하고** `--mono` 에서는 `GeistMono` 가 그린다. **옛 판의 이 목록은 `├ │` 를 조건 없이
  「검증됨」에 올려 두었다** — 그 산출물들이 mono 자리에 썼기 때문에 맞았던 것이고
  (`runs/iteration-2/qms` 는 `│` 를 쓰는데 폰트 전량이 예상 계열이다), sans 자리에는 그대로
  적용되지 않는다

- **없다**: `└`(U+2514) — **이 목록이 실측과 어긋나 있었다.** it.15 에서 두 런이 독립적으로
  찾았다. Pretendard 에 없어 PDF 가 `AppleSDGothicNeo` 를 끌어오고, **`check_html.py` 는
  통과시키고 `to_pdf.py` 만 잡았다.** 한 런이 후보 14자를 단독 렌더로 하나씩 확인해 이 글자만
  걸러 냈다. 지금은 `check_html.py` 의 폰트 축에 들어 있다

**폴더 트리는 mono 자리에 그린다**(`<pre>`·`code`·`.m` — `--mono` 체인이 걸리는 곳). 거기서는
`├─`·`│` 가 안전하다. 마지막 가지는 `└` 대신 **들여쓰기나 `·`** 로 닫는다 — `check_html.py` 의
폰트 축은 **글자 단위라 자리를 가리지 못해** mono 자리의 `└` 도 실패로 잡는다(오탐이지만 그
검사를 자리 인식으로 고치는 것은 설계 변경이라 하지 않았다). **sans 자리에는 박스 드로잉을 쓰지
않는다** — 셋 다 이탈한다.

**마크다운을 그대로 쓰지 않는다.** 강조는 `<b>`·`<strong>` 이고 `**...**` 는 HTML 에서
서식이 아니라 **문자 그대로 찍힌다.** 실측(it.15)에서 한 산출물의 인용 안 23곳과 본문 4곳에
`**` 가 그대로 나왔다 — `check_html.py` 가 인용 밖은 어긋남으로, 인용 안은 경고로 잡는다.
**원문이 마크다운 파일이어도 인용할 때 `**` 는 `<b>` 로 옮긴다** — 마크다운 기호는 그 파일의
서식이지 내용이 아니다.

## 인용 부호 안에는 원문 한 조각만 넣는다

`.q` 안에 **표의 여러 행이나 불릿 여러 개를 이어 붙이지 않는다.** 실측에서 세 산출물이 이렇게
했고 채점자들이 인용 결함으로 셌다 — 원문에 그런 문장이 없기 때문이다.

| 하지 않는다 | 대신 |
|---|---|
| *"장바구니 \| cartBtnEpsrYn 연동 \| CartUnit UI만"* 처럼 표 행을 `\|` 째 넣는다 | 표 행은 **우리 표로 옮긴다.** 인용은 그중 한 셀의 문구만 |
| 불릿 셋을 `/` 나 `·` 로 이어 한 인용으로 만든다 | 각각을 따로 인용하거나, 요약은 **인용 밖 서술**로 쓴다 |
| 여러 줄 코드블록을 한 줄로 접어 인용한다 | `<code>` 로 넣고 `.q` 를 쓰지 않는다 |

**한정어를 떼지 않는다.** *"기본 조회 단위"* · *"현행 … 실측값"* · *"신규 존"* 같은 수식어가
대상을 못 박는다. 떼고 인용하면 다른 것과 부딪히는 것처럼 보여 **없는 충돌이 생긴다** —
실측 거짓 양성 네 건이 전부 이 모양이었다.

표기를 바꿔야 할 때(폰트에 없는 글자·줄바꿈)는 **뜻이 바뀌지 않는 범위에서** 바꾸고 그 사실을
`eval_metadata.json` 에 남긴다. 원문자 `①`→`1` 처럼 뜻이 같은 치환은 괜찮다.

## 편집 함정

**한글 리터럴 치환은 `perl -i -pe`** 로 한다(플래그 없이). `-CSD` 를 붙이면 입력이 문자로
디코딩되는데 스크립트의 한글 리터럴은 바이트여서 **매칭이 조용히 실패한다.** 반대로
`\x{21C4}` 같은 코드포인트 치환은 `-CSD` 가 필요하다.

**표를 손으로 늘릴 때 `</td>` 를 빠뜨리기 쉽다.** 브라우저가 조용히 복구하므로 화면으로는
안 보이고 인쇄 레이아웃만 깨진다. 표를 건드린 뒤에는 `check_html.py` 를 돌린다.
